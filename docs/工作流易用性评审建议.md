# 工作流易用性评审建议

> 目标：让普通用户（非技术人员）也能独立完成工作流的搭建、调试与维护。
> 评审范围：整体交互 / 每个节点 / 能力体系三个维度。
> 优先级标注：🔴 高（普通用户的核心障碍）/ 🟡 中 / ⚪ 低。
> 依据：后端 `backend/app/services/workflow/`、前端 `frontend/src/components/workflow/` 及相关页面的代码实际行为（2026-09 评审）。

## 现状基础（做得好的地方）

- 中文错误提示普遍带修复指引（列出可选值、示例语法、设置入口路径）；
- 模板市场零输入安装：自动建表/复用表、示例数据、默认停用防误触、notes 汇总待办；
- AI 生成带字段名自动纠错（align 清洗）与 notes 回执；
- 保存期图结构强校验（单起点、DAG、foreach 接线规则）；
- 免登审批链接体验简洁、移动端友好。

---

## 一、整体易用性（系统级）

### 🔴 1. 保存前校验几乎为零 —— 最高优先级 ✅ 已实现（2026-09-27）

**现状**：保存只查"名称非空"，必填项靠 label 上的 `*`，含 `{` 的模板表达式直接跳过类型校验，错误全部延迟到执行期才暴露。普通用户的路径是：配错 → 保存成功 → 启用 → 跑挂 → 看不懂报错。

**建议**：
- 保存时跑完整 `validate_definition`，把结果**标注到画布节点上**（红点 + 面板内字段级报错定位），而不是只弹一句 toast；
- 增加图级检查：未连线的孤儿节点、条件/多路分支的悬空出口（提示"该分支永远不会执行"）、必填项为空、引用了不存在的 table_id；
- 对模板表达式做静态变量路径校验（见第 3 条）。

### 🔴 2. 无撤销/重做 + 删除节点无确认 ✅ 已实现（2026-09-27）

**现状**：删除节点一点就删，误删即丢全部配置；全仓库无 undo/redo。

**建议**：
- 删除节点弹轻量确认（或删后 5 秒可撤销的 toast）；
- 实现 undo/redo（vue-flow 的 nodes/edges 状态快照即可，Ctrl+Z / Ctrl+Y）。

### 🔴 3. 变量体系是普通用户最大的隐性门槛 ✅ 已实现（2026-09-27）

**现状**：
- 语法是单花括号 `{...}`，与用户从 `{{}}` 形成的肌肉记忆冲突，只有 placeholder 在教；
- 路径写错**静默渲染为空串**，不报错不提示——填错表现为"通知内容是空的"，排查链路（试运行 → 详情页 → 展开节点 → 看 input_json 裸 JSON）普通用户走不完；
- 多处占位符需手动替换（`{nodes.x.records.0.字段名}` 中的"字段名"），等于要求用户懂数据结构。

**建议**：
- VariablePicker 选记录字段时直接生成**完整可用路径**（含数组下标），消灭"手改占位符"场景；
- 试运行后若变量渲染为空串且路径不合法，运行详情里给黄色警告"变量 `{nodes.q_1.recordd}` 未取到值，是否想填 `{nodes.q_1.records}`？"（模糊匹配建议）；
- 长期可兼容 `{{}}` 输入（保存时归一化），或在 Picker 和帮助文案里统一强调语法。

### 🟡 4. 运行状态不回显画布，调试要来回跳页 ✅ 已实现（2026-09-27）

**现状**：调试路径是"画布 → 试运行 → 弹窗 → 跳详情页 → 看 timeline → 回画布改 → 再试运行"。

**建议**：
- 试运行后在画布节点上直接回显状态（绿/红/灰角标 + 耗时），点节点在配置面板顶部展示该次运行的输入/输出摘要；
- 运行详情页 timeline 点节点可跳回画布并定位；
- 节点输入输出的裸 JSON `<pre>` 换成可折叠树形查看器。

### 🟡 5. 审批没有聚合待办页 ✅ 已实现（2026-09-27）

**现状**：审批人要从站内通知翻链接或摸到 run 详情页，审批一多必漏。

**建议**：加「我的待办」页（或通知页加"待审批"Tab）：列出所有 waiting 状态的审批节点，登录态直接通过/驳回，免登链接保留给外部场景。

### 🟡 6. 画布操作效率 ✅ 已实现（2026-09-27）

- 节点面板支持**拖拽入画布**（目前只能点击），点击新增落点改为"找空位"而非固定斜线叠加；
- 加 MiniMap（vue-flow 自带组件，成本极低）；
- 添加节点后自动弹出配置面板并聚焦第一个必填项；
- 「整理画布」在 AI 生成/模板安装后自动触发一次。

### ⚪ 7. 列表与市场的查找能力 ✅ 已实现（2026-09-27）

- 工作流列表加搜索 + 状态筛选（运行中/已停用/最近失败）+ 分页；
- 模板市场加搜索和分类标签（通知/审批/报表/AI），15 个模板已到需要筛选的规模。

## 二、逐节点建议

### 触发器（TriggerForm） ✅ 已实现（2026-09-27，watch_fields 多选下拉二期已有）

| 优先级 | 建议 |
|---|---|
| 🔴 | **cron 可视化构建器**："每天/每周几/每月几号 + 几点"下拉生成 cron，高级模式才暴露表达式；或接 AI（"每天早上 9 点"→ 表达式）。目前预设之外要求用户懂 cron 语法 |
| 🟡 | record_updated 的 `watch_fields` 改为表字段多选下拉（现为自由填写，填中文显示名会监听失效） |
| 🟡 | webhook/form 生成 URL 后给"复制并测试"按钮（webhook 可发一条测试请求验证连通） |

### 逻辑类 ✅ 已实现（2026-09-27）

| 节点 | 优先级 | 建议 |
|---|---|---|
| condition / switch | 🔴 | `record`（判断对象）是第一个卡点：默认自动取最近上游节点输出（有 trigger.record 时默认 `{trigger.record}`），提供"判断对象"专用选择器代替裸文本框；FiltersEditor 字段框从自由文本升级为下拉（保留手输为高级选项） |
| foreach | 🟡 | 说清 max_items 默认 50 的截断语义；循环体未连回本节点时保存前就提示（现在靠保存报错） |
| date_calc | ⚪ | 基准时间给快捷选择（今天/明天/本周一…映射 `now` 变量）；offset 给常用预设（+1 天/+7 天/-30 天） |

### 数据类 ✅ 已实现（2026-09-27）

| 节点 | 优先级 | 建议 |
|---|---|---|
| query_records / update_record | 🔴 | filters 的「字段」从自由输入升级为字段下拉 + 操作符 + 值三段式（操作符/值控件已按字段类型适配，只差字段选择） |
| create_record / update_record | 🟡 | 选表后 field_mapping **按 schema 预填必填字段行**（标红星），用户只填值，不用回忆字段名 |
| aggregate | 🟡 | aggs 的 field 按上游字段下拉；试运行后显示结果预览（"共 N 条，求和 = X"）建立信心 |

### AI 类 ✅ 已实现（2026-09-27）

| 节点 | 优先级 | 建议 |
|---|---|---|
| llm_transform | 🟡 | ① `output_format=json` 时引导填写输出键名清单，并让下游 VariablePicker 能列出这些键（现在"AI JSON 输出·键名"要手写）；② TemplateInput 中变量**高亮渲染**，与普通文字视觉区分 |

### 动作类 ✅ 已实现（2026-09-27；接收人扩组织内未做）

| 节点 | 优先级 | 建议 |
|---|---|---|

| send_message | 🟡 | 通道配置缺失的检测提前到保存时（现在执行时才报"请到设置-通知渠道配置"，指引好但出现太晚） |
| sub_workflow | 🟡 | 选定子流程后自动列出其需要的 `{trigger.params.xxx}` 参数清单，生成 params 表单而非手写 JSON |

### 人工类 ✅ 已实现（2026-09-27；审批人解除好友限制未做）

## 三、能力维度（结构性降低门槛的新能力）

| 优先级 | 能力 | 说明 |
|---|---|---|
| 🔴 | **"检查问题"按钮（lint）** ✅ 已实现（2026-09-27） | 保存/启用前一键体检，输出问题清单（缺必填、悬空分支、变量疑似拼错、通道未配置、监听字段不存在），点击定位到节点。把散落的校验整合成一个用户可感知的动作，投入产出比最高 |
| 🔴 | **试运行沙盒** ✅ 已实现（2026-09-27） | 目前试运行需先保存且真实执行（真写表、真发通知）。试运行时动作类节点默认"模拟执行"（只记录将发送的内容不真发），确认后再真实跑——让普通用户**敢于试错**的关键 |
| 🟡 | **节点级示例配置** ✅ 已实现（2026-09-27） | 节点目录接口补 example_config，左侧面板加节点时可选"空白 / 示例"起点。15 个模板已证明"照着改"比"从零配"门槛低，把经验下沉到单节点 |
| 🟡 | **AI 辅助扩展到节点级** ✅ 已实现（2026-09-27） | 配置面板放"AI 帮我配这个节点"（"筛选过去 7 天金额大于 1000 的记录" → 生成 filters JSON）；以及"解释这个流程在干什么"（接手别人工作流时） |
| 🟡 | **失败主动通知** ✅ 已实现（2026-09-27） | 跑挂后给归属人发站内通知（现在失败是静默的），附失败节点、原因、一键跳详情 |
| ⚪ | **流程自述** ✅ 已实现（2026-09-27） | 列表页直接展示一句话"这个流程在干什么"（AI 生成的 description / 模板的 notes），降低协作理解成本 |

| ⚪ | **版本快照与回滚** | 每次保存留版本，可回滚；配合 undo/redo 覆盖"改坏了想回去"的场景 |

---

## 落地建议：先做三件事

1. **保存前校验 + 画布标错**（一.1）—— 打掉"配错不知道"；
2. **变量路径静态校验 + Picker 生成完整路径**（一.3）—— 打掉"错了不敢试"的源头；
3. **试运行沙盒 + 画布状态回显**（三.2 + 一.4）—— 打掉"试了看不懂"。

这三件直接消除普通用户"配错不知道、错了不敢试、试了看不懂"的三大核心障碍。
