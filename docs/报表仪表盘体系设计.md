# 报表体系设计 v3 —— 布局为中心 · 块级多数据源

> v3 重设计：抛弃"一个报表绑一张表"的旧模型与"弹窗编辑 + 设计器"双入口过渡形态。
> 新模型：**报表 = 命名数据集 ×N + 自包含区块 ×N + 页签栅格画布 + 推送**。
> 本文替代 v2 版《报表仪表盘体系设计》的前两章；已落地的栅格/联动/导出分节等机制保留，语义以本文为准。

## 0. 设计目标

1. **任何报表都能做**：一张仪表盘混排多张表的数据（订单 + 客户 + 库存同屏）；
2. **一个入口**：布局设计器即报表编辑器，没有第二套 UI；
3. **渐进披露**：默认拖字段即成图，专家可下沉到关联/计算字段/表达式；
4. **机制正交**：数据集管"数据从哪来"，区块管"怎么展示"，布局管"摆在哪"，推送管"怎么发"。

## 1. 核心概念模型

```
报表（Dashboard）
├── 数据集 datasets[]      命名、可复用：基表 + 左关联 + 计算字段
├── 区块 blocks[]          自包含：dataset_id + 可视化配置 + 口径方式
├── 布局 layout            页签 × 24 列栅格（纯摆放，不含数据语义）
├── 推送 schedule/push     定时、邮件、群机器人
└── 设置                   名称、描述、主题
```

关键变化：**区块不再共享模板的单一 table_id**，每个区块通过 `dataset_id` 绑定自己的数据源。
数据集在模板级命名复用——同一张"订单"数据集可以喂给 10 个区块，改一处全部生效。

## 2. 数据模型 v3

`report_templates` 表（新增 `datasets_json` 列；`table_id`/`source_json`/`filters_json` 退出新模型，仅作旧数据回退）：

```jsonc
{
  "name": "经营周报",
  "range_json": { "mode": "this_week", "start": null, "end": null },  // 全局口径：只有时间范围，不再有 date_field
  "datasets_json": [
    {
      "id": "d1", "name": "订单", "base_table_id": 12,
      "joins": [{ "table_id": 15, "on": [{"left": "customer_name", "right": "cust_name"}], "prefix": "客户." }],
      "computed_fields": [{ "name": "加权金额", "expr": "amount * iff(客户.level=='A',2,1)", "type": "decimal" }]
    },
    { "id": "d2", "name": "库存", "base_table_id": 20, "joins": [], "computed_fields": [] }
  ],
  "blocks_json": [
    {
      "id": "b1", "type": "chart", "title": "等级金额",
      "dataset_id": "d1",                 // 绑数据源（text 块可无）
      "date_field": "created_at",         // 全局口径作用在该数据集的这个日期字段上；null=不随全局口径
      "range_mode": null,                 // null=跟随全局；"this_month" 等=覆盖（原 range_override 简化）
      "chart_type": "bar", "group": {...}, "agg": "sum", "field": "amount",
      "on_click": "drill"                 // drill | link
    },
    {
      "id": "b9", "type": "filter", "title": "等级",
      "dataset_id": "d1", "field": "客户.level",
      "target": { "mode": "same_dataset" }       // 作用域：同数据集区块 | {mode:"blocks", block_ids:[...]}
    }
  ],
  "layout_json": { "version": 1, "grid": {...}, "pages": [...] },
  "schedule_json": {...}, "push_json": {...}
}
```

### 2.1 口径语义（多数据源下的时间过滤）

- **全局口径** = 时间范围（mode/start/end），不再有全局 date_field；
- 每个数据区块声明自己的 `date_field`（该数据集内的日期字段，含 created_at/updated_at）——全局范围逐块套用到各自的日期字段上；
- `date_field: null` → 该块不做时间过滤（如"总库存"）；
- `range_mode` 非空 → 该块用独立时间范围（如全局本周 + 某卡今年累计）；
- 查看页顶部的口径切换改全局范围，所有跟随块联动刷新。

### 2.2 筛选组件与联动的作用域

多数据源下"一个筛选过滤全部区块"不再天然成立，改为**显式作用域**：

| 机制 | 作用域规则 |
|---|---|
| filter 筛选组件 | `target.mode: same_dataset`（默认，作用于同 dataset_id 的区块）或 `blocks`（勾选目标区块） |
| 图表联动（on_click=link） | 固定作用于与点击块**同 dataset_id** 的其他区块（同一份数据才有意义），无需配置 |
| 下钻 | 仅自身，不变 |

后端实现：viewer 筛选规则带 `dataset_id` 标签，求值区块时只叠加匹配该块 dataset 的规则。

## 3. 设计器 UX（唯一入口）

```
┌──────────────────────────────────────────────────────────────────┐
│ ← 经营周报        [总览][明细][+]      设置 | 试运行 | 保存        │
├────────────┬────────────────────────────────────┬────────────────┤
│ 数据源      │  栅格画布（点状背景）                │ 区块配置        │
│ ▸ 订单 ▾   │  ┌────┐┌────┐┌──────────┐         │ （点选块出现）   │
│   ·金额     │  │stat││stat││  chart   │         │  标题           │
│   ·客户.等级│  └────┘└────┘└──────────┘         │  类型专属配置    │
│   ·加权金额 │  拖字段入画布 → 智能成图             │  数据源 [订单▾] │
│ ▸ 库存 ▾   │                                    │  口径 [跟随全局▾]│
│   ·数量     │                                    │  日期字段 [..▾] │
│ ─────────  │                                    │  筛选条件       │
│ + 添加数据源 │                                    │  删除区块       │
│ 未放置区块  │                                    │                │
└────────────┴────────────────────────────────────┴────────────────┘
```

- **数据源面板**：数据集为树（数据集 → 字段，含关联/计算字段徽标）；「添加数据源」= 选表 → 自动建数据集；点数据集名旁的 ⚙ 打开数据集编辑器（关联/计算字段抽屉，即现"数据源"抽屉升级）；
- **区块换源**：右侧面板可切换区块的 dataset（同名字段尽量保留映射，类型冲突的配置项清空并提示）；
- **模板设置抽屉**：名称/描述/主题/定时推送/webhook/AI 生成——原弹窗的所有模板级能力收编于此，弹窗退役；
- **新建报表**：列表页「新建」→ 只填名称 → 直接进设计器；
- 其余已定型的交互不变：拖拽/缩放/页签/撤销重做/自动排版/试运行/未放置抽屉。

## 4. 引擎与接口

### 4.1 求值流程（run_template 重构）

```
for block in blocks:
    ds = datasets[block.dataset_id]           # 数据集定义
    (table_or_records, fields) = resolve(ds)  # 按 dataset 缓存，同数据集只解析一次
    range = block.range_mode or global_mode
    start,end = resolve(range) if block.date_field else None
    rules = viewer_rules.match(block.dataset_id) + block.filters
    result = eval(block, ...)
```

- 数据集解析缓存：同 dataset_id 的区块共享子查询/记录集（10 个区块同数据集只解析一次）；
- **权限**：run/export/drill/保存时，对 datasets 里出现的每张表（含关联表）逐张 `get_table_access`；
- 下钻/导出/推送/邮件全部改为逐块数据集驱动（导出分节逻辑不变）。

### 4.2 接口变化

- `ReportTemplateIn`：`table_id` 不再是必填语义，新增 `datasets: list[dict]`；`filter_fields`/`source` 标记废弃（仅旧数据回退）；
- run/drill 的 viewer 筛选规则增加 `dataset_id` 维度；links 同理（联动天然同数据集，前端只需传 field/value）；
- AI 生成升级：输出 datasets + blocks + layout 完整草稿。

## 5. 兼容与迁移（不动存量数据）

**运行期合成**：模板无 `datasets_json` 时，引擎在内存中合成
`datasets = [{id: "_default", base_table_id: 旧table_id, joins/computed: 旧source_json}]`，
每个区块视为 `dataset_id=_default, date_field=旧range.date_field`，`filter_fields` 合成等效 filter 规则——旧模板**不改一行数据照常运行**。

**保存即升级**：设计器打开旧模板 → 内存合成 v3 结构 → 保存时写回 v3 格式（datasets_json 落库，table_id 保留只读展示"原主表"）。无迁移脚本、无停机。

## 6. 实施路线

**一期：引擎与数据模型（≈2 天）**（✅ 已完成）
1. ✅ `datasets_json` 列 + schema + validate（数据集 id 唯一、block.dataset_id 存在、date_field 属于该数据集、filter 块 target 合法）；
2. ✅ run/drill 逐块数据集解析 + 缓存 + viewer 规则按 dataset 匹配 + 逐表权限；
3. ✅ 运行期旧格式合成 + 冒烟 10.16（json+物理混合数据集同屏、filter 作用域、逐块口径、联动隔离）；旧用例（10.5~10.15）全部保持通过。

**二期：设计器收编（≈2.5 天）**（✅ 已完成）
4. ✅ 数据源面板（数据集树 + 添加数据源 + 数据集编辑抽屉）+ 区块换源（按名重映射、冲突清空提示）+ 拖字段成图绑源；
5. ✅ 模板设置抽屉（名称/全局口径/推送/AI）+ 新建直进设计器 + ReportEditor 弹窗退役删除；
6. ✅ filter 块作用域配置 UI + 旧模板打开自动升级（合成数据集、块补 dataset_id/date_field、filter_fields 转筛选组件块插入首页顶部）。

**三期：体验封顶（≈1.5 天）**（⬜ 未开始）
7. AI 全量生成（datasets+blocks+layout）+ 主题 + 场景模板库；
8. 小程序（页签 + 单列降级 + 多数据源渲染）；自定义 SQL 出口（按需）。

## 7. 风险与权衡

| 风险 | 对策 |
|---|---|
| 作用域规则对小白复杂 | filter 块默认 same_dataset 零配置；blocks 模式折叠为高级 |
| 区块换源造成配置悬空 | 换源时按字段名重映射，冲突项清空 + toast 列出；保存前校验兜底 |
| 多数据集 N 倍查询 | 数据集级解析缓存；同数据集区块合并记录集；推送/导出复用同一 run 结果 |
| 旧报表语义漂移 | 运行期合成保证 100% 旧行为；冒烟保留全部旧用例 |
| 全局口径有块不跟随（date_field=null）用户困惑 | 查看页在该块标题旁显示"不随时间筛选"小徽标 |
