# 易用性与界面美观改进建议

> 目标：让普通用户（非技术人员）在整个产品中少走弯路、少误操作、看得舒服。
> 评审范围：全局框架（导航/顶栏）+ 全部 30 个页面 + 关键共享组件。
> 优先级标注：🔴 高（普通用户的核心障碍 / 高危误操作 / 链路断裂）/ 🟡 中 / ⚪ 低。
> 依据：前端 `frontend/src/` 各页面代码实际行为（2026-10-11 评审），行号随代码演进可能漂移，以功能点为准。
> 记事本（Notes.vue）已于 2026-10 完成富文本化重做（wangEditor + 目录树 + AI 写作），不在本文重点之列。

## 一、全局框架（最高杠杆）

### 🔴 1. 侧边导航无分组，最多 16+ 项平铺 ✅ 已实现（2026-10-11）

**现状**：功能（数据表/导入/记事本/报表/工作流/思维导图）、协作（通知/好友/用户组）、管理（组织与成员/角色/审计）、平台（租户/套餐/用户）、计费、设置全部平铺（App.vue:8-73），角色越多越长，无分组、无折叠。

**建议**：
- 按 `el-menu-item-group` 分组加标题：**工作区**（数据表/导入 Excel/记事本/报表/工作流/思维导图）、**协作**（通知/好友/用户组）、**管理**（组织与成员/角色管理/审计日志）、**平台**（平台租户/套餐配置/用户管理）、**账户**（套餐与用量/设置）；
- 高频项（通知）位置提前；导航支持折叠成窄栏（只留图标）。

### 🔴 2. "设置"与"系统设置"命名撞车 ✅ 已实现（2026-10-11）

**现状**：`设置`（App.vue:66，平台超管，内容是模型服务/SMTP/MCP）与 `系统设置 > 基础设置`（App.vue:69，租户管理员，内容是公司名）名字几乎相同、归属不同角色、内容完全不同；"系统设置"子菜单只有一个子项，多套一层点击。

**建议**：`设置` 改名「集成设置」或「AI 与通知」；「系统设置」拆掉折叠，「基础设置」平铺进「账户」分组。

### 🟡 3. 顶栏信息架构浪费 ✅ 已实现（2026-10-11）

**现状**：顶栏左侧只有一个空的 `#topbarActions` Teleport 挂载点（App.vue:77），没有页面标题/面包屑，切换页面后没有位置感；通知铃铛只在侧边菜单挂角标（App.vue:32），不符合常见习惯。

**建议**：顶栏左侧显示当前页面标题（各页注册或按路由映射）；右上角加通知铃铛图标 + 未读角标，点击直达通知页。

### 🟡 4. 全局一致性体系缺失 ✅ 已实现（2026-10-11）

- **品牌色四套并存**：EP 默认蓝 #409eff、AI 紫 #9b59b6、登录页链接紫 #7c3aed、助手渐变蓝紫——建议收敛为 CSS 变量（主色/AI 色/语义色），自造紫色散用多处（Workflows token 数、RunDetail、Home 分区色）应统一引用；
- **时间格式不统一**：`created_at` 有的直出原串（TableList）、有的切片（DynamicTable fmt）——抽全局 `fmtTime` 工具，列表统一 `YYYY-MM-DD HH:mm`，详情/通知用相对时间（"5 分钟前"）；
- **空状态三种写法并存**：el-table #empty 插槽 / el-empty 组件 / 无处理——统一为带行动指引的空态（如"还没有好友，搜索用户名发送申请"是好范例，应推广到数据表、报表、用户组等）；
- **`.page-header` 同时定义在全局和各页 scoped**，易漂移，收敛到全局一处；
- 分页 layout 不统一：有的无 total（ShareView）、有的无 jumper（DynamicTable）、有的无每页条数切换（AuditLogs）——统一 `total + sizes + jumper`。

### 🟡 5. 危险操作确认分级混乱 ✅ 已实现（2026-10-11）

**现状**：删整表只一句 popconfirm（TableList.vue:29）；吊销 MCP token 零确认（Settings.vue:251）；审批通过/驳回零确认（Notifications、WorkflowRunDetail、PublicApprove）；AI 新建会话清空全部消息零确认（AssistantPanel.vue:216）；内联改成员角色一次误点即降权（Members.vue:18-25）。而"外部触达"类操作（报表推送群发、工作流立即执行）反而零确认。

**建议**：建立统一分级——
- L1 可逆操作：toast 反馈即可；
- L2 难恢复（删记录/删字段/清空）：popconfirm 指明对象（"删除「张三」这条记录？"）；
- L3 不可恢复/外部触达（删整表/推送群发/吊销 token/审批决定）：弹窗确认，说明影响范围（"将向 3 个渠道推送""该角色下还有 5 个成员"）。

### 🟡 6. 离开保护覆盖倒挂 ✅ 已实现（2026-10-11）

**现状**：ReportLayoutDesigner 有完整 dirty + 确认 + beforeunload；而 WorkflowEditor（WorkflowEditor.vue:5-7）、MindMapEditor（MindMapEditor.vue:230-232）、DynamicTable 记录表单（误点遮罩/ESC 丢弃整表输入）全部裸奔——越深的编辑器越没保护。

**建议**：抽一个通用 `useDirtyGuard`（beforeunload + 路由守卫 + 返回按钮拦截），优先覆盖：工作流编辑器、思维导图编辑器、DynamicTable 记录表单。

### ⚪ 7. 其他框架问题 ✅ 已实现（2026-10-11）

- 订阅宽限/只读横幅不可关闭（App.vue:101-110），长期占 32px——加"本次不再提示"；
- 切换工作空间整页 `location.reload()`（App.vue:194）无 loading 过渡；
