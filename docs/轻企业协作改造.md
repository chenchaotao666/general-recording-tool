# 轻企业协作改造

实施日期：2026-10-19。

## 使用方式

右上角企业菜单集中提供：企业切换、新建企业、加入企业、我的企业。

- 一个账号可以创建多个企业，也可以加入多个企业。个人空间继续作为独立空间存在。
- 新建时填写企业名称，类型、行业、规模用于企业资料；不要求配置部门和角色。
- 企业创建者可在“我的企业 → 邀请同事”生成邀请码，或者向已注册的完整用户名发送邀请。
- 邀请码有效期为 7 天，每次生成新码会使旧码失效。持码用户先查看企业名称，再确认加入；加入身份固定为普通成员。
- “加入企业”同时展示收到的待处理邀请，可直接接受或忽略。
- “我的企业”显示企业同事；创建者/已有管理员可编辑企业资料，普通成员不显示管理入口。
- 数据表分享搜索已包含当前企业的有效成员，无须先互加好友。

## 数据协作方式

新建的轻企业采用“创建者管理、按数据分享”的方式。企业管理员可管理企业内数据表，其他成员默认访问自己创建的表、已接受的表分享，以及智能表中明确配置的全员/指定成员权限。

普通成员拥有基础功能入口和分享能力。分享仍使用查看、新增、编辑、删除开关，直接分享需接收者接受。智能表保留其原有内容权限工具，第一次添加指定成员授权时使用“全员无权限”的基线。

数据表列表在轻企业中按当前企业过滤；切换企业后返回首页并刷新页面，避免编辑页继续携带上个企业的资源 ID。

本次没有改变记事本、画板、报表等各模块既有的资源权限模型。企业身份和同事目录已统一，后续需要逐模块增加新的分享方式时，可复用此目录。

## 移除的功能与兼容

移除了“基础设置”“角色管理”“组织与成员”“审计日志”四个前端页面、侧边栏入口和首页可选快捷入口；旧地址转到首页。企业改名合并到“我的企业 → 企业信息”。

旧部门树、数据范围配置、审计查询 API 不再注册；成员部门/角色修改接口不再注册。底层审计写入、成员关系和存量授权数据保留，角色维护接口仅平台管理员可访问，以兼容平台用户管理和已有数据。

存量企业保留已有数据授权策略。通过新入口创建的企业会有 `enterprise_profiles.lightweight = true`，才使用新的默认分享策略；给旧企业补充资料或邀请码不会自动改变其授权策略。

## 部署与数据结构

- 新增 `enterprise_profiles` 表，保存企业资料、邀请码、有效期和轻企业标志。现有启动流程的 `create_all` 会创建该表。
- 新增隐藏的 `light_enterprise` 套餐种子：初始 20 个成员席位、3 张表、5000 条记录、512 MB 存储空间；沿用当前免费版的其他基础权益和配额宽限机制。平台可调整这些种子权益，重启不会覆盖已有设置。
- 新企业不修改用户全局部门/上级字段，所以创建、加入多个轻企业不会互相覆盖组织信息。
- 新增 `/api/enterprises` 创建、详情、资料更新、邀请码生成/预览/加入接口。
- 修复 `/api/tenants/switch` 未直接校验有效成员关系的问题。

更新代码后需重启后端，以创建新表并补充套餐种子；前端需使用本次构建产物。

### 存量数据库创建失败修复

旧 SQLite 的企业主键可能复用已删除企业的编号；如果用量等关联记录仍保留该编号，创建企业会触发唯一键冲突。`v7_tenant_ids` 迁移将企业主键改为不复用编号，并把序列推进到所有现存 `tenant_id` 引用的最大值。迁移前沿用启动流程备份数据库，保留原有企业及历史关联数据。回归测试覆盖孤立用量记录、迁移重复执行、删除企业后再次创建。
