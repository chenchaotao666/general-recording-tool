# 首页工作台设计

> 状态：设计稿 ｜ 2026-10-09
> 目标：可自由定制的首页。用户按需把「数据表、菜单功能、通知、待办、报表…」组织成自己的工作台，
> 后续新功能以插件方式接入为新的卡片类型，无需改首页框架。

## 1. 需求拆解

用户原话拆解为四个能力点：

| 能力 | 设计映射 |
|---|---|
| 首页自由分块、块大小自由定制 | **分区（Section）**：栅格画布上的容器块，可拖拽位置、可拖拉改大小 |
| 块里内容自定义 | 分区里放**卡片（Card）**，卡片类型可选、卡片自身有配置项 |
| 小块类型：数据表/菜单/通知/待办…后续新功能可被选入 | **卡片类型注册表（插件机制）**：新功能注册一个类型即可在"添加卡片"里出现 |
| 小块顺序灵活排序、可分类显示 | 两层分类：**分区是第一层分类**（如"常用表""待办中心"）；**分区内可再建分组（Group）做二次分类**（如"常用表"分区里再分"生产""销售"两组）。卡片在组内/跨组拖拽排序 |

信息架构三层：

```
首页（每用户一份布局）
 └─ 分区 Section（大块：标题 + 栅格位置/尺寸 + 配色可选）   ← 第一层分类
     └─ 分组 Group（可选，0~N 个：标题 + 折叠态 + 组内卡片序） ← 第二层分类
         └─ 卡片 Card（小块：类型 + 配置 + 排序）
             └─ 类型插件：table / menu / notifications / todos / report / ...
```

- 分区不建分组时，卡片直接挂在分区下（等同只有一个隐式默认组），简单场景零负担；
- 分组可折叠/展开（折叠状态入布局，记住用户习惯）；
- 卡片支持**跨组、跨分区拖动**，也可用卡片菜单"移动到…"精确转移（触屏/拖不准时兜底）。

## 3. 卡片类型（插件注册表）

前端一个注册表 `src/home/cardTypes.js`，新功能接入 = 加一条注册：

```js
// 每个类型：{ type, name, icon, defaultSize, component, configForm? }
registerCardType({
  type: 'table',            // 数据表快捷入口
  name: '数据表',
  icon: Grid,
  defaultSize: { w: 3, h: 2 },
  component: TableCard,     // 展示组件（查看态）
  configForm: TableCardCfg, // 配置表单（编辑态，选哪张表、显示什么）
})
```

P0 内置类型：

| 类型 | 内容 | 配置项 |
|---|---|---|
| `table` | 表图标 + 名称 + 记录数 + 最近更新；点击进 `/t/:id` | 选表；显示项开关（记录数/更新时间） |
| `menu` | 菜单功能入口（导入/记事本/报表/工作流/好友/用户组…） | 选功能（按当前用户权限过滤） |
| `notifications` | 最近 N 条通知 + 未读角标；点击进通知页 | 条数 N（默认 5） |
| `todos` | 待审批列表（pending-approvals）+ 未读通知数汇总 | 条数 N |

P1+ 扩展示例（验证插件机制）：`report`（报表卡片）、`notes`（最近笔记）、`workflow-run`（最近运行）、`clock/weather` 等纯展示卡。

权限规则：卡片渲染时自行做权限降级——无权限的数据表卡片显示"无权限"置灰态；菜单卡片按路由 meta/admin 过滤候选。

## 4. 布局与交互

### 查看态（默认）
- 分区按栅格渲染（grid-layout-plus 静态模式）；分区标题 + 分组 + 卡片网格。
- 分组有标题栏（组名 + 折叠/展开箭头）；未建分组的分区直接平铺卡片。
- 卡片即快捷入口：单击直达；通知/待办卡内列表项可点进详情。
- 右上角「自定义」进入编辑态。

### 编辑态
- 分区：拖移换位、右下角拖拉改大小（栅格对齐）、改标题、删除、新增分区（顶部「+ 添加分区」）。
- 分组：分区内「+ 添加分组」、改组名、折叠/展开、删除（组内卡片移入"未分组"）；分组标题栏拖动调整组的先后。
- 卡片：组内拖拽排序、**跨组/跨分区拖动**（拖到分组标题=移入该组末尾）；卡片上悬浮操作（配置/移动到…/移除）；「+ 添加卡片」弹出类型选择器（图标 + 名称 + 说明）。
- 编辑态不改即走有 dirty 提示（复用打印设计器的关闭守卫模式）。
- 「恢复默认」：系统内置默认布局（常用分区：我的数据表 + 待办 + 通知）。

### 栅格
- 12 列栅格，行高 ~80px；分区最小 3×2，卡片在分区内按自适应网格排列（卡片宽高比由类型 defaultSize 决定，区内不重排大小，只排序——小块大小由内容类型决定，避免两层缩放复杂度）。

## 5. 数据模型与 API

**每用户一份布局**，后端存 JSON（跨设备、可审计、管理员可预设默认）：

```python
# models.py
class HomeLayout(Base):
    __tablename__ = "home_layouts"
    id = Column(Integer, primary_key=True)
    user_id = Column(Integer, ForeignKey("users.id"), unique=True, index=True)
    layout_json = Column(JSON, default=dict)   # {sections:[{id,title,x,y,w,h,cards:[{id,type,config}]}]}
    updated_at = Column(DateTime, default=datetime.now, onupdate=datetime.now)
```

布局 JSON 结构（三层：分区 → 分组 → 卡片；`groups` 缺省表示不分组、卡片直接在 `cards` 里）：

```json
{
  "version": 1,
  "sections": [
    {
      "id": "sec_1", "title": "待办中心", "x": 0, "y": 0, "w": 6, "h": 4,
      "cards": [
        { "id": "card_1", "type": "todos", "config": { "limit": 5 } },
        { "id": "card_2", "type": "notifications", "config": { "limit": 5 } }
      ]
    },
    {
      "id": "sec_2", "title": "常用数据表", "x": 6, "y": 0, "w": 6, "h": 4,
      "groups": [
        {
          "id": "grp_1", "title": "生产", "collapsed": false,
          "cards": [{ "id": "card_3", "type": "table", "config": { "table_id": 18 } }]
        },
        {
          "id": "grp_2", "title": "销售", "collapsed": false,
          "cards": [{ "id": "card_4", "type": "table", "config": { "table_id": 21 } }]
        }
      ],
      "cards": []   // 未分组卡片（显示在各分组之后，或编辑态拖入组内）
    }
  ]
}
```

- `groups[]` 数组顺序即分组显示顺序；`collapsed` 记住折叠态；
- 卡片在 `cards[]` 数组中的下标即顺序（组内排序 = 改数组顺序；跨组移动 = 从一个 `cards` 挪到另一个）。

API（`routers/home.py`）：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/home-layout` | 取当前用户布局；无记录 → 返回系统默认布局 |
| PUT | `/api/home-layout` | 整体覆盖保存（布局量小，无需增量） |

卡片数据不走新接口——各卡片组件直接调现有业务 API（表列表/通知/待办），首页布局接口只管"摆什么、摆哪"。

## 8. 风险与注意点

- **grid-layout-plus 已在报表设计器使用**，首页与其交互保持一致（同一套拖拽手感），注意两个页面不要同时注册全局样式冲突。
- 三层拖拽（分区拖移 / 分组排序 / 卡片跨组跨分区）是交互最复杂的部分：卡片拖动用 HTML5 DnD + 放置区高亮即可，**不要引入第二个拖拽库**；拖不准的场景用卡片菜单「移动到…」兜底。
- 分组删除时卡片并入"未分组"而不是连带删除，防止误删入口。
- 卡片组件必须**自治**：各自拉数据、各自处理 loading/无权限/空态，首页框架不感知业务。
- 布局 JSON 加 `version` 字段，后续结构演进时可做迁移。
- 删除某数据表/报表后，对应卡片渲染"已失效"占位而不是报错（卡片组件容错）。
